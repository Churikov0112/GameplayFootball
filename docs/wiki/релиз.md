# Релиз (упаковка и публикация)

Как из свежей сборки получаются релизные артефакты и где расставлены грабли. Процесс локальный —
CI в GitHub нет (см. [[открытые-вопросы]]).

## Артефакты и скрипты

| Платформа | Ассет | Скрипт |
|---|---|---|
| Windows x86/x64 | `GameplayFootball-v<ver>-win32-<arch>.zip` | `tools/release/package_windows.ps1` |
| Linux | `GameplayFootball-v<ver>-linux-x86_64.tar.gz` | `tools/release/package_linux.sh` |
| macOS | `GameplayFootball-v<ver>-macos-<arch>.zip` | `tools/release/package_macos.sh` |

`dist/` в `.gitignore` — артефакты не коммитятся, выкладываются в GitHub Releases
(`gh release create v<ver> dist/...`).

## Процесс (на примере macOS)

1. Собрать: `cmake -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="$(brew --prefix)"`,
   затем `cmake --build build --parallel 1` (на MacBook Air M2 параллельная сборка вешает комп).
2. `cp -R data/. build/`.
3. Упаковать: `/opt/homebrew/bin/bash tools/release/package_macos.sh <ver>` — **bash 4 обязателен**
   (`declare -A`), системный macOS bash — 3.2.
4. Проверить пакет: `otool -L` — без `/opt/homebrew` и `@rpath`; `codesign --verify --deep --strict`;
   запуск, игра, закрытие окна — в `Contents/Resources/data/log.txt` штатное
   `Shutting down OpenGLRenderer3D thread`, без `[ERROR]`/`FATAL`.
5. `gh release upload v<ver> dist/GameplayFootball-v<ver>-macos-<arch>.zip`.

## Устройство .app-бандла

Игра резолвит все пути относительно CWD, а macOS запускает .app из `/` — поэтому:

- настоящий бинарник — `Contents/MacOS/gameplayfootball-bin`;
- `Contents/MacOS/gameplayfootball` — launcher-скрипт: chdir в `Contents/Resources/data` → exec `-bin`;
- данные — `Contents/Resources/data` (`media/`, `databases/`, `football.config`);
- все несистемные dylib (SDL3, SDL3_image/ttf, Boost, кодеки, `libjxl_cms` и пр.) — в
  `Contents/Frameworks`, install names переписаны на `@executable_path/../Frameworks`.

Следствие: `log.txt` и `saves/` пишутся внутрь бандла — из пользовательской папки (скачанный zip)
это работает, с read-only носителя (DMG, защищённый `/Applications`) нет. Запись отражена в
[[открытые-вопросы]].

## Подпись и Gatekeeper

Бандл подписан ad-hoc и **не нотаризован** (нет Apple Developer). На первом запуске macOS
предупреждает о непроверенном ПО: правый клик → «Открыть», либо
`chmod -R u+w` + `xattr -cr GameplayFootball.app`.

## Ловушки

- `package_macos.sh` собирает dylib-замыкание через `otool -L` и резолвит `@rpath`/`@loader_path`
  в brew lib (`$(brew --prefix)/lib`). Не выбрасывай ссылки `@rpath` из замыкания и не пропускай
  перезапись `-id` — на машине без brew приложение не загрузится (классический кейс:
  `libjxl_cms.0.12.dylib` выпадала из бандла, пока не резолвили `@rpath`).
- brew ставит dylib с правами `r--r--r--`: копирование в бандл требует `cp -Lf` (дубли одного
  basename в замыкании), снятие карантина — `chmod -R u+w` перед `xattr -cr`.
- В бандле dylib-файлы перезаписывает и переподписывает `install_name_tool`/`codesign` — правки
  должны идти до финального `codesign --deep`.
